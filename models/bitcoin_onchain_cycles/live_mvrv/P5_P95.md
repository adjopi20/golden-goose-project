# Strategy: Four-year MVRV P5/P95 v1

- Asset/style/timeframe: BTC, spot long-or-cash adaptive cycle valuation, completed daily UTC observation.
- Hypothesis: relative historical valuation may adapt when absolute market valuation extremes shift. Relative thresholds can drift without a matching price move and are not forecasts.
- Window: exactly 1460 previous contiguous daily Z observations, current day excluded; linear quantiles. This is four-year-like, not leap-year-aware calendar slicing.
- Entry: account is cash, no pending action, valid current data and full warmup, Z < past-window P5. Strict inequality, no crossing requirement.
- Exit: account holds BTC, no pending action, valid full-warmup data, Z >= past-window P95.
- Position size: full this-account cash on entry, full this-account BTC on exit. Initial funding 50% of system capital, no periodic rebalancing, local compounding.
- SL / hard loss cap / trailing / partial TP / time stop: none; indicator-only exit, matching tested rules. No rollover.
- Risk: P5 is rare and can miss a cycle. Adaptive thresholds do not guarantee reduced DD; full account BTC exposure can lose substantially. No additional price/volume/regime filter.
- Execution/data/fees/guards: `CONTRACT.md`, shared engine. Raw full history from 2010-07-18 is required for the expanding Z denominator even though thresholds use the last 1460 observations.
- Historical evidence: existing P5/P95 historical sensitivity, post-hoc selection. Same max DD as P10/P95 in the evaluated main horizons; not an independently validated improvement. No deployed forward trade metrics yet.
- Continue/review/retire: paper acceptance criteria in `CONTRACT.md`; provider revisions or data faults block proposals, not invent exits.
- Dependencies: Coin Metrics source, shared Z/threshold calculation, common engine and durable ledger; no browser, CVDD, NUPL or LLM.
- Change log: 2026-10-03 v1, operator-selected adaptive branch; parameters frozen for forward testing.
